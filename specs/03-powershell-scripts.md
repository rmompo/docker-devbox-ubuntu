# 03 - PowerShell scripts

## Context
Daily management of images and containers must be fast, without remembering Docker commands or full names.

## Reasoning
1. Every resource carries the prefix -> scripts can list them and offer them in a menu.
2. Picking from a list avoids typing errors -> common navigable menu (spec 01).
3. Each script does one thing -> one script per operation.
4. Destructive and create operations work on a single item at a time -> single selection.

## Decision

| Script | Behavior |
|---|---|
| `dkdb-image-create` | Asks only for the image name (default `devbox-ubuntu`, so `dkdb-devbox-ubuntu`; the prompt shows the version it will be tagged with) and builds `dkdb-<name>:<version>`. |
| `dkdb-image-delete` | Menu of `dkdb-` images; deletes the chosen one (single selection). |
| `dkdb-container-create` | Asks for the image (as `dkdb-image-create` does; the default is shown with the highest compatible version that will be used), container name, user and the host projects and tools paths (spec 04) and, if Mutagen is installed, the projects volume type (menu; spec 08) and, last, the ports to publish (spec 09; the question explains the format; `-Ports <list>` skips it); the `bash` volume is fixed. The engine (Docker Desktop or an engine inside WSL) is detected and the host paths of the bind mounts are translated when needed (spec 04). |
| `dkdb-container-start` | Menu of **stopped** `dkdb-` containers, or `-Container <name>`. For a Mutagen container the Mutagen daemon is always started and the registered sessions are listed with their state, but none is changed (`Invoke-DevboxSyncPick -KeepOnly`; `dkdb-mutagen-manage` changes them, spec 08). |
| `dkdb-container-stop` | Menu of **running** `dkdb-` containers, or `-Container <name>`. It never touches Mutagen (daemon or session). |
| `dkdb-container-connect` | Menu of **running** `dkdb-` containers, or `-Container <name>`; opens bash with `docker exec -it -u <user>`. For a Mutagen container it does the same as `dkdb-container-start` (daemon started, sessions listed, none changed) before the shell; the shell opens even if that fails. |
| `dkdb-container-delete` | Menu of **stopped** `dkdb-` containers, or `-Container <name>` (the `[y/N]` confirmation is asked either way) (a running one must be stopped first); asks `[y/N]` confirmation because the container's home and installed AI client are lost; the host bind-mounted folders are not touched. For a Mutagen container it also terminates that container's Mutagen session (only that one, never the daemon), provided the daemon is running; otherwise `dkdb-mutagen-service` (Clean) removes it later. |
| `dkdb-mutagen-service` | Menu of actions on Mutagen as a whole (one daemon per user, no container): **Start** (checks whether the daemon runs and starts it if not), **Stop** (flushes the running Mutagen containers and stops it; all Mutagen sessions stop), **State** (executable, version, daemon, number of sessions) and **Clean** (lists the orphan `dkdb-` sessions, whose container no longer exists, in a menu with an option for all of them and terminates the chosen ones after a `[y/N]`; the host folders are not touched) (spec 08). |
| `dkdb-mutagen-manage` | The container comes first: `-Container <name>` (with or without the prefix) or a menu of the Mutagen containers, running or stopped, which starts with `(all containers)` (it goes straight to Status of every container); then a menu of the actions that apply to that container (Add and Modify only when it is running): **Add** (a folder, a new session, in a **running** container: Add (relative) / Add (absolute) of the synchronization menu with `Invoke-DevboxSyncPick -AddOnly`, both folders checked, the new session activated and the active ones it covers paused), **Modify** (the menu without the Add options, `-NoAdd`: Keep (no changes), Custom, All (registered), None (pause all)), **Remove** (one registered session: `[active]`/`[paused]` list, `[y/N]`, pause and terminate; the only way to remove a session of a living container) and **Status** (cards with the state and conflicts of each session and a progress summary, `So far X of Y files`, with whether it moved since the previous query) (spec 08). The host and container folders are never touched. |
| `dkdb-verify` | Checks the installed package against `manifest.json`: every listed file must exist and have the version of the manifest; files that the manifest does not list, or lists as removed (`dkdb-update` deletes them), are reported as notes. Exit code 1 when something is inconsistent. |
| `dkdb-version` | Prints every version: the project and the image version of the manifest, each file (manifest against its header), PowerShell, Docker, Mutagen (against the minimum), each image and each container (with its projects volume badge, MUTAGEN-SYNC or VOLUME-P9) with its compatibility. Works without Docker for the first sections. |
| `dkdb-update` | Updates the installed package from the repository. Optional `-Branch <branch or tag>` (default `main`; letters, digits, `.`, `_`, `-`, `/`). Downloads `manifest.json` to a temporary folder, lists the files that are missing or whose version differs (every file of the manifest, `install/dkdb-install.ps1` and `install/dkdb-uninstall.ps1` included) and the installed files that the `removed` list of the manifest names (only paths inside `scripts/` or `install/`, never one listed in `files`), asks `[y/N]`, downloads them to the temporary folder, checks that each `# Version:` header equals the manifest and only then copies them (`manifest.json` last) and runs the integrity check. It deletes the removed files after copying (manifest last). Nothing changes if a download or a check fails; nothing else is deleted, so files of your own in those folders stay; a `dkdb-update` older than this feature does not delete, so the removed files go away the next time it runs. It tells you to rebuild the image when the image version is no longer compatible. |
| `dkdb-info` | Prints how everything is set up: shared root and folders, PATH, Docker, images, containers (state, user, volume type, mounts, published ports) and, only when a container uses Mutagen or the daemon has sessions, Mutagen (daemon and sessions with their progress); without synchronization the section and its hint do not appear. Layout (same in `dkdb-info.sh`): SECTIONS in capitals, PROPERTIES in capitals with dots up to the values, values wrapped to the console width; host paths cyan, container paths magenta; reverse-video words MUTAGEN (red), MUTAGEN-SYNC (yellow), VOLUME-P9 (red), READ-ONLY (green), READ-WRITE (red); `[running]` green and `[stopped]` red. |

- **Location:** `scripts/ps1/`.
- **Native programs:** Mutagen is run through `Invoke-DevboxNative` when its output is read: it captures standard output and error output separately, with the exit code, because in Windows PowerShell 5.1 the error lines of a program mixed in with `2>&1` become verbose error records (and can stop a script that sets `ErrorActionPreference` to `Stop`). `mutagen daemon start` is not run through it: the background daemon would keep the pipes open.
- **Help and manual:** every script takes `-Help` (its usage, through `Show-DevboxHelp`) and `-Man` (its manual, through `Show-DevboxMan`; spec 01), before doing anything else.
- **`-Container`:** every script that chooses an existing container from a menu (`dkdb-container-start`, `-stop`, `-connect`, `-delete` and `dkdb-mutagen-manage`) also accepts `-Container <name>`, with or without the `dkdb-` prefix, which skips the menu. The name is checked against the same list the menu would show (`Resolve-DevboxContainerName` in the common file); when it is not in it, the script warns with the available ones and exits with 1. A script that finds no candidate at all keeps printing its message and exiting with 0.
- **Synchronization menu:** only `dkdb-mutagen-manage` (Modify and Add) shows it; `dkdb-container-start` and `dkdb-container-connect` call `Invoke-DevboxSyncPick -KeepOnly` instead (no menu: checks, starts the daemon, lists the sessions, changes nothing). No script has sync parameters, only `-Help` and `-Man` (and `-Container`). The menu is `Invoke-DevboxSyncPick` (common file): Keep (no changes), Custom (a checklist of the registered sessions), All (registered), None (pause all), Add (relative) and Add (absolute). It returns Ok and Active; the hierarchy rules are in spec 08. The parameters are native PowerShell with `[CmdletBinding(PositionalBinding = $false)]`, so PowerShell itself rejects stray arguments. The menu needs an interactive console, as the container menus do.
- **Version and integrity (spec 01):** every script prints its own version and the project version when it starts. `dkdb-image-create` and `dkdb-container-create` (they create things) check the installed package against `manifest.json` (`Assert-DevboxIntegrity`) and stop if it is inconsistent. `dkdb-image-create` tags the image with the image version (`image` in the manifest), never `latest`. `dkdb-container-create` uses the highest tag of `dkdb-<name>` that is compatible with the image version that the scripts expect; when there is none it uses the highest older tag with a warning, and stops only when no image of that name exists. After updating the scripts nothing that uses an image or a container created before is blocked. **`dkdb-container-start` and `dkdb-container-connect` are never blocked by versions**: an inconsistent package (`Assert-DevboxIntegrity -WarnOnly`) or an image whose version (`DEVBOX_IMAGE_VERSION`, read from the container environment) is not compatible with the one the scripts expect (`Test-DevboxContainerVersion`) only produces a warning and a `Next:` hint (rebuild the image and recreate the container); the container keeps working with the image it was created from. `dkdb-container-stop` and `dkdb-container-delete` never check versions.
- **State file:** after the synchronization menu, `dkdb-container-connect`, `dkdb-mutagen-manage` (Status) and `dkdb-mutagen-service` (Stop) call `Update-DevboxContainerState`, which writes `~/.devbox-state` inside the container for `dkdb-info.sh` and `dkdb-version.sh` (spec 05 and 08). A failure to write it is silent: it never blocks anything.
- **Colors in `dkdb-container-connect`:** it passes `-e TERM=xterm-256color -e COLORTERM=truecolor` so the default Ubuntu `.bashrc` enables the colored prompt even when `docker exec` provides a plain `xterm`.
- **Bash volume:** `dkdb-container-create` mounts the folder `scripts\bash` that sits next to `scripts\ps1` (resolved by `Get-DevboxBashPath` in the common file) read-only. Nothing is copied.
- **Shared root:** never stored; `Get-DevboxRoot` (common file) deduces it from the script location, `<root>\devbox\scripts\ps1`, and stops with a message if the scripts are somewhere else. The default tools path is `<root>\tools` (`Get-DevboxDefaultToolsPath`).
- **Installation:** the scripts are installed and added to the user PATH by `install/dkdb-install.ps1` (spec 07), so they can be called by name.
- All of them load the common file holding the prefix and `Select-DevboxItem`.
- `.ps1` files are ASCII with LF line endings; prompts and messages are in English.

## Consequences
- No script touches Docker resources that do not start with `dkdb-`. The only exception is `dkdb-mutagen-service` (Stop): Mutagen has one daemon per user, so stopping it stops all your Mutagen sessions, not only the `dkdb-` ones.
- `dkdb-container-connect` does not start stopped containers: use `dkdb-container-start` first.
